## What the game has and what it would need

- Already in data: none of the above options. Counterspell and Find Familiar exist (Familiar Friend and the familiar
  feats build on Find Familiar). The revised Arcana Unleashed spells aren't in data/spells yet, so they'd be new
  files, not edits.
- Data: one JSON per option in data/subclasses, data/backgrounds, data/feats, data/spells, data/magic_items,
  data/items, in the existing formats (ADR 0005, schemas in data/schemas). New `source.book` codes: `HoF`, `AiF`,
  `AU`, added to tools/data/data_sources.py and docs/rules/data_sources.md. Feat categories already cover origin,
  general, fighting style and epic boon. Each option's `implemented` flag and docs/rules/coverage.md rows as usual.
- Combat: the Ravenloft options plug into about 25 hooks through combat/ravenloft_features.gd, each called next to
  the matching ClassFeatures hook in encounter.gd, features.gd, feature_actions.gd, spell_caster.gd and reactions.gd.
  These books need the same (Bladesong, Spellfire, the Purple Dragon Knight's dragon companion, Arcane Shot,
  Winter Walker, Scion of the Three, Noble Genies, Vestige Patron, the school wizards, the new feats and spells).
  Rather than a second copy of every call, turn those call sites into a loop over a list of book modules and add
  combat/faerun_features.gd and combat/arcana_features.gd. That's a combat/ change, so agree it with whoever owns
  shared combat behaviour (the Spell and ability audit thread) first.
- New systems the game doesn't have: Circle Magic, faction renown, Bastion facilities and evolving magic items.
  Each needs an owner call on whether it belongs in a Barovia campaign before any work.

## The readiness flag (owner decision 2026-10-07: hide until ready)

Every entry from the Faerun books and Arcana Unleashed (`source.book` FRHoF, FRAiF or AU in data/backgrounds,
data/feats, data/spells, data/subclasses and data/magic_items) carries `"playable": false`. While it does, the game
leaves the entry out of character creation, level-up and spell choices and random treasure (`Compendium.playable`,
`Compendium.all_playable`); a lookup by id still finds it, so a save that names one still loads.

To turn an entry on once all of its rules work in the game, set `"playable": true` in its file (or delete the line).
Nothing else needs to change. `tests/unit/test_playable_gate.gd` checks that whatever is marked `false` is left out of
the choices and treasure, and that it still loads by id.

## Refinements

- iPad now declares all four orientations and removes Godot 4.7.2's deprecated full-screen-only export policy. iPhone retains both landscape orientations. The iOS native bridge identifies the device idiom independently of window width and selects the matching sensor policy. Desktop startup is unchanged.
- The isolated export adjusts the generated plist once, retaining identity, launch storyboard, scene manifest and unrelated fields. Simulator builds and signed archives validate the actual packaged policy before reporting success. No duplicate plist keys or edits to desktop export settings.
- Inventory returns from single-pane inspection to its bag/detail split when an iPad window widens, retaining the selected item, search and quantities. Deferred page reflow also clears old minimum-size bounds when narrowing the already-open page.
- Narrow character sheets use two stat columns. Phone and portrait iPad spell controls move below readable names/tags; short landscape windows combine Prepare Spells and the caster summary so spell rows are visible immediately. Section and reading position survive width/height composition changes.
- Creation reflows ability choices and appearance portraits; resizing retains choices, preview/step state and scroll position. Old mobile step controls detach before measuring their replacements. The party roster reflows without changing the chosen party.
- Loot keeps desktop-style horizontal rows with icons, names, quantities, weight and actions. Narrow windows use compact labels and margins; a visible touch-sized list viewport is reserved. Footer actions wrap without starving the list. Resize preserves recipient, coins/items and any open inspection.
- Mobile selected-value pickers use a single-line, clipped summary. Their touch picker still exposes full choice names. This fixes a reproducible deferred-layout queue exhaustion with long item-code variants in a narrow window. Engine limits and test assertions were not relaxed.
- Full-height dialogue busts move outward in portrait/narrow windows so both faces remain separate without shrinking their height. The compact bottom reading panel and speaker portrait remain.
- Save/backup empty states wrap within the window. Combat targeting commands move above End Turn only when there is insufficient horizontal room.

The quiet phone world/minimap/Menu/hold-Reveal HUD, dismissible combat Actions, compact text, desktop-style loot, item/spell icons and large dialogue busts/portraits remain in place. Desktop builders and input paths retain their presentation.

## Design comparison

[Apple TN3192](https://developer.apple.com/documentation/technotes/tn3192-migrating-your-app-from-the-deprecated-uirequiresfullscreen-key) calls for a launch screen, all iPad orientations and layouts that adapt to changing scene bounds. The previous exported app still opted into full-screen compatibility; the revised export and layout matrix address that gap. Actual Stage Manager window dragging and external-display transitions still need native/hardware qualification beyond the synthetic resize matrix.

[Godot 4.7 DisplayServer](https://docs.godotengine.org/en/4.7/classes/class_displayserver.html#class-displayserver-method-screen-set-orientation) requires the project sensor setting for runtime iOS orientation selection. The iOS override enables it; device idiom determines phone versus tablet policy.

[Larian's official iPad listing for Divinity: Original Sin 2](https://apps.apple.com/us/app/divinity-original-sin-2/id1458655678) documents touch plus connected input devices. Our comparison emphasizes equivalent command access and inspect-before-commit behavior across touch/controller input, rather than adding permanent controls to the world. Automated controller tests remain distinct from physical accessory qualification.
